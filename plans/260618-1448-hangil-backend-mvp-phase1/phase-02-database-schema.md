# Phase 02 — Database Schema + Neon Connection

## Context Links
- Spec: STEP 2. Conventions: snake_case cols, Drizzle-only, no manual migrations.

## Overview
- **Priority:** P1
- **Status:** pending
- **Description:** Define all 6 Drizzle tables in `db/schema.ts` and Neon connection in `db/index.ts`.

## Key Insights
- snake_case DB columns; Drizzle maps to camelCase TS via field names.
- pgEnum needed for: plan(free/pro), track(k_culture/topik), level(beginner/intermediate/advanced).
- Better Auth needs its own identity/session storage. **Decision point (see Risk):** Better Auth either (a) manages its own tables and our `users` row links by id, or (b) we let Better Auth use this `users` table as the user model. Spec lists app fields ON `users`, so plan = Better Auth uses/extends this `users` table; sessions/accounts in Better Auth-managed tables generated by its drizzle adapter.

## Requirements
**Functional — tables (all id uuid PK, default gen):**
- `users`: email unique not null, name, plan enum default 'free', track enum nullable, streak_count int default 0, last_studied_at timestamp nullable, created_at default now, updated_at default now.
- `lessons`: title_vi, title_ko, track enum, level enum, order_index int, content jsonb, is_published bool default false, created_at default now.
- `vocabulary`: korean, romanization, vietnamese, example_sentence_ko, example_sentence_vi, audio_url nullable, lesson_id FK→lessons, created_at default now.
- `user_cards`: user_id FK→users, vocab_id FK→vocabulary, easiness real default 2.5, repetitions int default 0, interval_days int default 1, next_review_at timestamp default now, last_reviewed_at timestamp nullable.
- `user_progress`: user_id FK→users, lesson_id FK→lessons, completed_at timestamp nullable, score int nullable.
- `journal_entries`: user_id FK→users, content_ko text, ai_feedback jsonb nullable, created_at default now.

**Non-functional**
- Indexes: `user_cards(user_id, next_review_at)` for due-card query; `lessons(track, level)` for filtered list; unique `user_cards(user_id, vocab_id)` to prevent dup init.
- FK onDelete: cascade for user-owned rows (user_cards, user_progress, journal_entries); restrict/cascade vocabulary→lessons (cascade).

## Architecture
- `db/index.ts`: `drizzle(neon(DATABASE_URL))` from `@neondatabase/serverless`, export `db`.
- `db/schema.ts`: source of truth; drizzle-kit reads it for push/migrate.
- Data flow: schema → drizzle-kit → Neon DDL. Runtime: services import `db` + tables.

## Risk Assessment
| Risk | L×I | Mitigation |
|------|-----|-----------|
| Better Auth table model conflicts with our `users` shape | **H×H** | Resolve adapter strategy before push: confirm Better Auth drizzle adapter table names; either map to `users` or add separate `auth_*` tables. Run Better Auth schema gen in P4, reconcile here if needed. |
| uuid default needs pgcrypto/gen_random_uuid | M×M | Use `defaultRandom()` (Drizzle emits gen_random_uuid, native in PG13+/Neon). |
| jsonb `content` shape unvalidated | L×M | Validate via Zod at write time (P5); schema stores raw jsonb. |
| float drift on easiness | L×L | `real` acceptable for SM-2; precision non-critical. |

## Security Considerations
- No PII beyond email/name. FK cascade ensures user deletion removes owned rows (GDPR-style cleanup).
